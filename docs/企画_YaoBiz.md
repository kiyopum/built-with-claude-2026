# YaoBiz（ヤオビズ）— 決定済み機能まとめ

（2026-11-03 きよさんが別チャットで固めた内容をそのまま保存。変更するときはきよさんに確認してから）

**一行コンセプト**
眠っている商いを、空いた時間で掘り起こして売る。売るものはあるのに売り方がわからない地域の小さな事業者と、時間に縛られずに働きたいパートナー（主婦）をつなぎ、ヒアリング→商品化→販売→成果記録までを一本にする。

**役割（3つ）**
- パートナー：事業者さんに行ってヒアリングし、音声かメモを入れる人
- 事業者さん：Claudeが起こした商品ドラフトを確認してOKを押す人
- 管理者（YMM）：明細を確認する人

**画面（3つだけ、これ以上増やさない）**

1. ヒアリング画面（パートナー用）
   - 訪問先の店を選ぶ／新規登録
   - Claudeが業種から質問リストを10問程度生成して表示（素人でも聞き漏らさない）
   - **録音ボタンをど真ん中に**。音声入力をメインにし、文字起こし結果を編集可能なテキスト欄に流し込む
   - 手入力でも同じ欄に入るので、音声が使えない環境でも手だけで完結
   - 録音は何回でも追加可、まとめてClaudeに渡す
   - **カメラボタン**：スマホから撮影かアルバム選択、1商品に複数枚、1枚目がメイン画像。余裕があればClaudeに写真も渡して紹介文の精度を上げる
   - 送信するとClaudeが商品ドラフトを生成

2. 商品ドラフト確認画面（事業者さん用）
   - 商品名・紹介文・価格案・おすすめ理由・想定客を1件1枚で表示。1回のヒアリングから2〜3件
   - 事業者さんは「このまま公開」「修正を頼む」「却下」の三択。修正は一言入れると再生成
   - 公開商品は公開ページに一覧表示、商品ごとにURL発行
   - **シェアボタン**（Web Share API：スマホならLINE/Instagramへ、PCならURLコピー）＋**QRコード表示**（店頭に貼れる）
   - **購入ボタンはStripe Checkout（テストモード）**へ。配送先・在庫は扱わない

3. 成果明細画面（パートナー・管理者用）
   - WebhookでCheckout完了を受けて注文を保存、料率計算を自動実行
   - 注文ごとに「事業者さん／YMM／パートナー」の取り分を並べて表示、合計欄あり
   - 料率：売上の1割がYMM、そのうちの設定割合がパートナー、残りが事業者さん
   - 契約条件（業務内容・報酬計算方法・支払期日）を画面上に常時表示（フリーランス新法の明示義務対応）
   - 送金はアプリ内で行わない。本番はStripe Connect（マーケットプレイス型）で自動送金する設計、とREADMEに一文

**Stripe（ハッカソン版）**
- テストモードのAPIキーを環境変数に。本番キーは公開リポに入れない
- 商品公開時にStripeのProduct/Priceを自動作成
- デモはテストカードで本物の決済画面を撮る

**技術**
- Next.js、SQLiteかSupabase（写真はSupabase Storage）、Anthropic APIでClaude呼び出し
- 認証は最小限。デモは役割切り替えボタンで代用可
- データは全部ダミー（事業者名・生産者名・金額は架空）

**やらないこと**
- 送金・分配の実送金、在庫管理、チャット機能、スマホアプリ化

**実装の優先順位**
ドラフト生成 → 音声入力・文字起こし → Stripe Checkout → 明細 → 写真 → シェア・QR

**デモの舞台**
地域の商品を集めたセレクトショップ形式の健康食品店。パートナーが事業者さんと棚の前で話す→Claudeが商品ページを起こす→事業者さんがOK→売れたら明細に記録、の一本。

**未確定で残っているもの**
- 文字起こしエンジン：Web Speech API（無料・速いが雑音に弱い）か、Deepgram等（精度）か。録音ファイルは同時保存しておく方向で保留中

**README の方針**
